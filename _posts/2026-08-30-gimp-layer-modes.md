「乗算にすると暗くなる」「スクリーンにすると明るくなる」。ペイントソフトを使っていると、こうした説明をよく見かける。

でも、乗算は本当に何をしているのだろう。なぜ乗算は影に向いていて、スクリーンは光に向いているのだろう。オーバーレイは、何と何を重ねているのだろう。

この記事では、普段使っているレイヤーモードを、できるだけ数式として眺めてみる。対象は、少し理系寄りの絵描き・クリエイター。細かな実装を追いかけるのではなく、「このモードは画素にこういう計算をしているのか」と分かることを目指す。

ペイントソフトによって、同じ名前のモードでも細かい処理は違う。そこで、ここでは処理を確認しやすいGIMPをひとつの例にした。GIMPがすべてのソフトの代表という意味ではない。今回は、いろいろなソフトで名前や用途が比較的通じやすいモードに絞る。

## レイヤーモードは「上下の色から新しい色を作る関数」

まず、完全に不透明な2枚のレイヤーを考える。

```text
下の色 = D
上の色 = S
結果   = f(D, S)
```

`f` の中身を入れ替えたものが、乗算・スクリーン・差の絶対値などのレイヤーモードである。

RGBの各チャンネルを `0.0`〜`1.0` に正規化して考える。たとえば、赤チャンネルについて `D = 0.3`、`S = 0.4` なら、乗算は次のようになる。

```text
0.3 * 0.4 = 0.12
```

3つのチャンネルに同じ計算をすれば、RGBの結果になる。

### まずは数値を入れてみる

下の色を `D = 0.25`、上の色を `S = 0.4` とすると、代表的なモードはこうなる。

| モード | 計算 | 結果 |
| --- | --- | ---: |
| Add | `0.25 + 0.4` | `0.65` |
| Multiply | `0.25 * 0.4` | `0.10` |
| Screen | `1 - (1-0.25)(1-0.4)` | `0.55` |
| Overlay | `2 * 0.25 * 0.4` | `0.20` |

この数字だけでも、乗算が暗くなり、スクリーンが明るくなる理由が見えてくる。

ただし、実際のレイヤーには透明度がある。レイヤーモードは、単に `f(D,S)` を計算して終わりではない。

## 実際には「色」と「透明度」を別々に考える

レイヤーモードを理解するとき、次の2段階に分けると分かりやすい。

1. 上下の色から、モード固有の色 `B` を作る
2. `B` を、上のレイヤーの不透明度や透明部分を使って下に重ねる

```text
B     = f(D, S)
結果  = アルファ合成(D, S, B)
```

ここで、

| 記号 | 意味 |
| --- | --- |
| `D` | 下のレイヤーの色 |
| `S` | 上のレイヤーの色 |
| `B` | モードが作った色 |
| `αD` | 下のレイヤーの不透明度 |
| `αS` | 上のレイヤーの不透明度 |
| `p` | レイヤー設定の不透明度 |

マスク値を `m` とすると、上のレイヤーが実際に効く不透明度は、概念的には次になる。

```text
αS' = αS * p * m
```

通常の合成では、出力の不透明度は次の式になる。

```text
αout = αS' + (1 - αS') * αD
```

下のレイヤーと上のレイヤーがどちらも完全に不透明なら、`αD = 1`、`αS' = 1` なので、最終的には `B` だけが残る。だから普段は、乗算を `D*S` と説明できる。

一方、上のレイヤーが50%不透明なら、乗算で作った色をそのまま表示するのではなく、乗算結果と下の色の間を補間する。レイヤーの不透明度を下げると「乗算の濃さ」が変わるのはこのためである。

## Normal（通常）

上のレイヤーを、そのまま下に重ねるモードである。

```text
B = S
```

下のレイヤーが完全に不透明なら、上のレイヤーが100%不透明のときは上の色だけが見える。上が半透明なら、上の色と下の色の間になる。

「何もしない」ように見えるが、透明度を含めると、Normalはレイヤー合成の基準になる大事なモードである。ほかのモードも、最後はNormalに似たアルファ合成の仕組みと組み合わされる。

## Multiply（乗算）

```text
B = D * S
```

`0.0`〜`1.0` の範囲なら、結果は必ず入力の小さい方以下になる。白 `1.0` を掛けても相手の色がそのまま残り、黒 `0.0` を掛けると黒になる。

この性質が、影・陰影・線画の色付けに向いている理由である。上のレイヤーに暗い色を置くほど、下の色を暗くする効果が強くなる。

例えば、下が `0.8`、上が `0.5` なら、

```text
0.8 * 0.5 = 0.4
```

となる。上のレイヤーを50%不透明にすれば、最終的には `0.4` と `0.8` の間の値になる。

## Screen（スクリーン）

```text
B = 1 - (1-D) * (1-S)
```

展開すると、

```text
B = D + S - D*S
```

とも書ける。

黒 `0` を入れると、

```text
1 - (1-D) * (1-0) = D
```

なので黒はほとんど何もしない。白 `1` を入れると、結果は `1` になる。Multiplyとは逆に、白い部分ほど下の色を明るくする。

光・ハイライト・発光表現に向いているのは、この性質による。黒背景に描いた光をScreenで重ねると、黒い部分を目立たせずに光だけを載せやすい。

例えば、下が `0.25`、上が `0.4` なら、

```text
1 - (1-0.25) * (1-0.4) = 0.55
```

となる。

## Add / Addition（加算）

```text
B = D + S
```

2つの色の光量を、そのまま足すと考えるモードである。明るい色同士を重ねると、すぐに白に近づく。

画面や8bit画像のように値を `0.0`〜`1.0` に収める場合は、一般に次のように扱う。

```text
B = min(1, D + S)
```

ただし、内部をfloatやHDRで扱うソフトでは、途中の値が `1.0` を超えたまま保持されることもある。「加算したら必ずその場で白になる」とは限らない。

発光、強いハイライト、光源の重なりを作るときに使いやすい。Screenよりも、明るさを直接押し上げる感じが強い。

## Subtract（減算）

```text
B = D - S
```

上の色を下の色から引くモードである。暗い色を作りやすく、色の差を利用した調整や、明るさを落とす処理に使える。

表示できる範囲より小さくなった値は、一般には `0.0` に収める。

```text
B = max(0, D - S)
```

例えば、下が `0.7`、上が `0.4` なら、結果は `0.3` になる。上が `0.8` なら `-0.1` だが、通常の表示範囲では黒 `0.0` になる。

なお、名前が似ているLinear Burnは、ソフトによっては別のモードである。Linear Burnの代表的な式は `D + S - 1` で、Subtractの `D-S` とは違う。ソフトをまたいで比較するときは、名前より式を見る必要がある。

## Darken（暗く）

```text
B = min(D, S)
```

下と上の色をチャンネルごとに比較し、暗い方を選ぶ。

赤だけ上の方が暗く、青だけ下の方が暗い場合のように、チャンネルごとに別々の色が選ばれる。そのため、単純に「暗い方の画像全体を選ぶ」処理ではなく、境界で色味が変わることがある。

白 `1.0` は相手より暗くならないので、ほとんど何もしない。黒 `0.0` は、そのチャンネルを黒にする。

2枚の画像から暗い線や影だけを残したいとき、あるいは白背景を消したいときに使われる。

## Lighten（明るく）

```text
B = max(D, S)
```

Darkenの反対で、チャンネルごとに明るい方を選ぶ。

黒 `0.0` は相手より明るくならないので、ほとんど何もしない。白 `1.0` は、そのチャンネルを白にする。

暗い背景を目立たせずに、明るい線や光だけを重ねたいときに使える。ただし、Darkenと同じくチャンネル単位の比較なので、画像全体の明るさだけを比較しているわけではない。

## Overlay（オーバーレイ）

Overlayは、下の色が暗いか明るいかで、Multiply寄りかScreen寄りかを切り替える。

```text
B = 2 * D * S                         (D < 0.5)
B = 1 - 2 * (1-D) * (1-S)             (D >= 0.5)
```

暗い下地ではMultiplyのように暗くなり、明るい下地ではScreenのように明るくなる。中間の `0.5` 付近を基準にコントラストを強める、と考えるとよい。

例えば `D = 0.75`、`S = 0.4` なら、下の色が明るいのでScreen側を使う。

```text
1 - 2 * (1-0.75) * (1-0.4) = 0.70
```

`D = 0.25` ならMultiply側になり、

```text
2 * 0.25 * 0.4 = 0.20
```

となる。

陰影を強めたり、テクスチャを下の明暗に沿わせたり、全体のコントラストを出したりする用途でよく使われる。上のレイヤーを50%グレーにすると、理想化した式では下の色をほぼ変えない。

## Difference（差の絶対値）

```text
B = abs(D - S)
```

下と上の色の差を、絶対値にして取り出す。順番を入れ替えても結果は同じである。

同じ色同士なら、

```text
abs(D - D) = 0
```

なので黒になる。白 `1.0` を重ねると、

```text
abs(D - 1) = 1 - D
```

となり、色が反転する。

2枚の画像の位置合わせ、塗り残しや差分の確認、色の比較に便利なモードである。見た目をきれいにするためだけでなく、「どこが違うか」を見つけるためのモードとして考えると分かりやすい。

## 半透明のレイヤーでは、式の結果をさらに混ぜる

ここまでの式は、上下のレイヤーが完全に不透明な場合の見え方である。上のレイヤーが半透明なら、モードが作った色 `B` と下の色 `D` の間を補間する。

下のレイヤーが完全に不透明なら、概念的には次のようになる。

```text
最終色 = αS' * B + (1 - αS') * D
```

例えば、半透明の黒をMultiplyで重ねても、黒一色にはならない。下の色を黒に近づけるだけである。半透明の白をScreenで重ねても、白一色ではなく、下の色を白に近づける。

この「モードの式」と「透明度による補間」を分けて考えると、レイヤーの不透明度を下げたときの挙動を予想しやすい。

## ソフトによる違いはどこに出るのか

この記事ではGIMPを具体例にしたが、他のペイントソフトで完全に同じ結果になるとは限らない。モードの名前が同じでも、細かい実装や表示のされ方が違うことはある。

それでも、Multiplyは「上下を掛ける」、Screenは「反転して掛けて戻す」、Overlayは「下の明暗で分岐する」という中心部分は、いろいろなソフトを理解するときの共通の足場になる。ここでは、その共通部分をつかむことを優先した。

## まとめ

レイヤーモードは、魔法のフィルターというより、画素ごとに同じ計算を繰り返す仕組みである。

- Normalは上の色をそのまま重ねる
- Multiplyは `D*S`。暗い色や影に向く
- Screenは `1-(1-D)(1-S)`。明るい色や光に向く
- Addは `D+S`。光量を直接足す
- Subtractは `D-S`。色や明るさを引く
- DarkenとLightenは、チャンネルごとに暗い方・明るい方を選ぶ
- Overlayは、下の明暗に応じてMultiplyとScreenを切り替える
- Differenceは `abs(D-S)`。2枚の差を見つける
- 半透明の場合は、モードの結果をさらにアルファ合成する

数式を全部覚える必要はない。まずは「何を足すのか」「何を掛けるのか」「どちらの色を基準に分岐するのか」を見るだけでも、レイヤーモードの挙動はかなり予想できるようになる。
